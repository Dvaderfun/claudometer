# R0 0.9.1 release preparation (2026-10-09)

The immutable v0.9.0 tag passed source/security and both production artifact
builds, then failed before publication because the SBOM output directory was
missing. It is retained as a failed unreleased attempt. v0.9.1 creates that
directory before scanning and uses sequence 2 with the same production key.

The owner explicitly authorized GitHub setup and publication of existing work.
ADR 0006 records deferring Windows Authenticode to v1.0 and retaining manual
bootstrap, Ed25519 manifests, exact-byte checks, protected approvals, immutable
tags/assets, and source/SBOM attestations. Provider credentials are untouched.

## Local evidence

- fmt, Clippy with warnings denied, all 168 tests, x64/ARM64 release builds.
- Privacy, dependency/license, workflow, and live infrastructure checks pass.
- Both PE architectures, VERSIONINFO 0.9.1, checksums, and original size gates pass.
- Local production public key/sequence embedded; both manifest signatures verify.
- Exact-artifact note renderer resolves hashes/sizes/public policy, rejects
  missing templates, and leaves no unresolved tokens in rendered notes.
- Isolated x64 demo safety: no files, registry/power changes, child processes,
  or provider connections. Five-start readiness median/p95: 46.239/56.803 ms.
- x64 1,145,344 bytes; ARM64 1,029,120 bytes. ARM64 initially failed the original
  size gate; removing only optional Ed25519 `fast` tables resolves it without
  changing policy or dependencies. Details are in the artifact ledger.

Private Ed25519 key backup is protected outside git under LocalAppData's
ClaudometerReleaseKeys directory. GitHub holds the private key only in the
protected `release` environment. Repository variables hold public policy.
Temporary existing GitHub authorization is supplied to the read-only release
infrastructure check and will be removed from the environment after publication.

Real ARM64 runtime, Narrator, and Windows publisher signing are incomplete and
disclosed in notes. Local signatures do not prove GitHub provenance/SBOM; the
tag workflow must produce and verify those before publication. Final GitHub
hashes must be generated from its exact tested binaries, not local copies.

Rollback: a new signed higher-sequence authorization or manual pre-bootstrap
binary; never mutate immutable tags/assets or delete safety/update journals.
