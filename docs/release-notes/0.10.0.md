# Claudometer 0.10.0 — clearer usage and Vibecode mode

## What changed

- Quota pace shows whether current use is on track, tight, or likely to reach
  the limit before reset. A small bar tick marks elapsed window time, the
  even-pace point. Disable pace colors in Settings to use percentage severity.
- Choose Used/Left percentages and Clock/Countdown reset times in Settings.
  Clicking a quota value or reset label changes the same preference everywhere.
  Claude sessions without a reset read Not started.
- Provider headers show Updating…, Outdated, or a short error warning while
  retaining same-account last-good values. The compact footer shows observation
  age and next update; its refresh action respects provider cooldowns.
- Vibecode mode combines idle-sleep protection with journaled lid-close
  protection. Turning it off or exiting restores previous lid settings. The
  flyout/Settings controls agree and explain what is active. It does not
  prevent manual Sleep, shutdown, network loss or battery exhaustion.
- Diagnostics is a compact support/Copy card; full sanitized details remain
  available through explicit Copy and UI Automation.
- Optional Use Codex CLI for usage reads additional quotas through an audited,
  isolated native CLI. It remains off by default: measured p95 is 2.198 seconds.
  Unsupported versions/ARM64 retain the direct compatibility source. The app
  never refreshes or writes provider credentials; no resident helper is added.
- Vibecode title and caption are vertically centered beside the icon/switch.

Portable release; no installer. **Windows executables are unsigned.** Windows
publisher/SmartScreen signing remains a v1.0 requirement. Signed manifests and
GitHub provenance establish the existing repository/workflow identity.

0.9.1 can use signed-manifest updates when automatic update checks are enabled.
Versions through 0.7.3 require a manual trust-root upgrade. For a manual update,
quit normally and complete any Vibecode recovery before replacing the binary.
Keep settings, cache and recovery files. Never delete a safety journal to bypass
an error. Verify the downloaded file before launching:

```powershell
$asset = Resolve-Path '.\claudometer-v0.10.0-windows-x64.exe'
$expected = '{{X64_SHA256}}'
if ((Get-FileHash -LiteralPath $asset -Algorithm SHA256).Hash.ToLowerInvariant() -cne $expected) {
    throw 'Claudometer SHA-256 mismatch'
}
gh attestation verify $asset.Path --repo Dvaderfun/claudometer --signer-workflow Dvaderfun/claudometer/.github/workflows/release.yml --source-ref refs/tags/v0.10.0
if ($LASTEXITCODE -ne 0) { throw 'Claudometer provenance verification failed' }
```

## Verification and limits

192 local tests, focused demo/UIA checks, timer checks and both architecture
builds pass. The protected release workflow checks the exact published assets,
signatures, checksums, SBOM and build attestations before publication.
Narrator speech, Selection/RangeValue and targeted accessibility events remain
incomplete. Real ARM64 runtime and physical lid-close sleep behavior are
unverified. This is not the completed v1.0 milestone.

Claude Code and Codex own sign-in and durable credentials. No provider token
refresh/write, telemetry, crash upload or automatic diagnostic export is added.
The tagged PRIVACY.md and docs/recovery/vibecode.md describe side effects and
recovery. Settings/cache/journal schemas remain compatible; an older binary
returns to its former UI and independent wake/lid controls.
