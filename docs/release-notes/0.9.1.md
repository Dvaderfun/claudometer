# Claudometer 0.9.1 — manual trust-root upgrade

**Install this release manually.** Versions through 0.7.3 cannot authenticate
the new update key and will not install this release automatically. After this
upgrade, updates require signed manifests and verified exact artifact bytes.

**Windows executables are unsigned.** Authenticode signing is deferred to
v1.0. GitHub provenance verifies the repository/workflow that produced the
download; it does not supply a Windows publisher identity or SmartScreen
reputation. This release has no installer and remains portable.

## What changed

- Provider state belongs to the UI thread. Account/generation/request checks
  reject obsolete work before requests, display changes, cache writes, or alerts.
- Bounded usage cache restores matching account/source data with its true age.
  Restored values stay cached, never alert, and never skip the first live poll
  except while an accepted persisted rate-limit cooldown remains active.
- Errors explain sign-in expiry, missing Claude usage scope, throttling,
  timeout, offline connection, and unexpected responses. UIA and tooltips
  expose recovery details without raw response bodies.
- Settings includes local Diagnostics and explicit Copy diagnostics. Support
  logs retain at most three 256 KiB files of fixed event codes. `--diagnose`
  and `--version` exit without network requests, CLI launches, file repair,
  log writes, or normal tray startup. Secrets and personal identifiers are excluded.
- Settings writes are validated and atomic, with a verified backup and
  malformed-file preservation. Unknown settings survive migration.
- Vibecode's wake lock is separate from the Advanced lid-close override.
  Persistent power changes use a durable journal, checked writes/read-back,
  and conservative recovery of the recorded power scheme.
- Portable updates verify signed manifest policy, architecture, version,
  sequence, expiry, exact size, and hash before writing a candidate. Journaled
  swaps and a bound readiness handshake retain the previous binary until commit.
- New installs default automatic update checks off; enable them in Settings.
  Existing settings migrate to enabled. Managed/ambiguous paths offer manual
  download rather than modifying package-managed executables.
- UI Automation names, Invoke/Toggle, and keyboard focus are available. Narrator,
  Selection/RangeValue patterns, and targeted dynamic announcements are incomplete.
- The release uses the measured `opt-level = "z"` size profile. Native Windows
  rendering and the single process architecture remain unchanged.

Claude Code and Codex still own credentials. Polling never refreshes or writes
them. Codex remains on the compatibility source; CODEX-01/02 are incomplete
because managed app-server reads can refresh and persist tokens. No telemetry,
provider response logging, crash upload, or resident helper is added.

## Legacy Vibecode recovery

Legacy `settings.json.vibecode_lid` values have no recorded scheme GUID. They
block a new lid override until the explicit **Restore** action journals and
verifies the saved AC/DC values on the current scheme.

If recovery is needed, quit normally and run the verified executable with
`--recover-vibecode`. A nonzero result means recovery is unresolved: retain
the journal, settings, backups, and preserved corrupt files. Never delete or
hand-edit a recovery journal to bypass the error.

Full privacy and recovery documentation is in the tagged source's `PRIVACY.md`
and `docs/recovery/vibecode.md`. Incomplete accessibility and ARM64 hardware
verification are disclosed here; this is not the completed v1.0 milestone.
